# Workflow: Context Windows & Communication Standard

แนวทางปฏิบัติสำหรับการสื่อสารระหว่าง AI และ USER เพื่อประสิทธิภาพสูงสุด

## 1. Context Health Monitoring (การรายงานสถานะความจำ)
เพื่อให้ USER ทราบสถานะ "ความสดใหม่" ของหน่วยความจำ AI:
- **เงื่อนไข:** เมื่อบทสนทนาเข้าสู่รอบการโต้ตอบที่ 10 เป็นต้นไป AI ต้องรายงานสถานะไว้ที่ท้ายสรุปงานเสมอ
- **รูปแบบการรายงาน:**
    - 🟢 **Green (Low-Medium):** หน่วยความจำแม่นยำ 100% สั่งงานซับซ้อนได้
    - 🟡 **Yellow (Warning):** เริ่มมีการ Truncation แนะนำให้ทำ Checkpoint ลงไฟล์ Workflow
    - 🔴 **Red (Critical/High):** ความจำเริ่มล้น เสี่ยงต่อการเกิด Bug แนะนำให้เปิด Session ใหม่
- **สิ่งที่ต้องระบุ:** ไฟล์ที่จำได้แม่นที่สุดในปัจจุบัน (Hot Files) และอาการทางความจำที่ตรวจพบ (ถ้ามี)

## 2. Post-Development Summary (สรุปหลังการแก้ไข)
- ทุกครั้งที่จบการแก้ไขโค้ดที่สำคัญ ต้องทำการอัปเดตไฟล์ `version.ts` และ `package.json` เสมอ
- หากเป็นลอจิกใหม่ที่มีความสำคัญสูง ให้ทำการสรุปหลักการทำงานลงใน Workflow ที่เกี่ยวข้องดั้งที่เคยทำใน `cast-stability.md`

## 3. Reference First Policy (การอ้างอิงความรู้เก่า)
- เมื่อเริ่มบทสนทนาใหม่ AI ต้องทำการสแกนไฟล์ในโฟลเดอร์ `.agent/workflows/` เพื่อดึงบริบทสำคัญก่อนเริ่มเขียนโค้ดเสมอ เพื่อป้องกันการแก้ไขลอจิกที่ตกลงกันไว้แล้ว
