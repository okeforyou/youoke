# 🛠️ YouOke Refactoring Policy (AI-Protocol)

นี่คือกฎเกณฑ์ในการรักษาคุณภาพโค้ด (Code Quality) สำหรับ AI Agent เพื่อให้โปรเจกต์ดูแลรักษาง่ายในระยะยาว:

## 1. ขีดจำกัดขนาดไฟล์ (File Size Limit)
* **ขนาดสูงสุด:** ไฟล์ Source Code ใดๆ (เช่น `.ts`, `.tsx`, `.py`, `.js`) ไม่ควรมีความยาวเกิน **500 บรรทัด (500 Lines of Code)**
* **ข้อยกเว้น:** ยกเว้นไฟล์ที่เป็น Configuration (เช่น `package.json`, ข้อมูล Data คงที่) หรือมีเหตุผลความจำเป็นทางสถาปัตยกรรมที่แบ่งไม่ได้

## 2. หน้าที่ของ AI เมื่อพบไฟล์ขนาดใหญ่ (Trigger & Action)
* หาก AI กำลังจะแก้ไขหรือเพิ่มฟีเจอร์ลงในไฟล์ที่มีขนาดเข้าใกล้ หรือ **เกิน 500 บรรทัด** AI **ต้องทำการ Refactor (แยกไฟล์) ทันที** ก่อนหรือหลังจากการเพิ่มฟีเจอร์นั้น
* การแยกไฟล์ (Splitting Files): ควรแยกตามบริบท (Separation of Concerns) เช่น:
    * แยก Routes/Endpoints ออกเป็นไฟล์ต่างๆ ตามหมวดหมู่ (สำหรับ Backend)
    * แยก UI Components ย่อยๆ ออกจาก Component หลัก (สำหรับ Frontend)
    * แยก Utility functions ออกไปไว้ในโฟลเดอร์ `utils/` หรือ `helpers/`
* AI ต้องทำการทดสอบ (Verify) หรือรัน Linter เสมอหลังการแยกไฟล์ เพื่อให้มั่นใจว่า Code ยังทำงานเชื่อมกันได้อย่างสมบูรณ์

> "ถ้าไฟล์ไหนที่เริ่มมีขนาดใหญ่เกิน เช่น เกิน 500 บรรทัด ให้ทำการ refactor เลย ให้ทำการแยกไฟล์เพื่อง่ายในการแก้ไขด้วย" - *บันทึกตามคำสั่งของ User*
